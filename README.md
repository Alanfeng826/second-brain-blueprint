# Second Brain Blueprint · 个人知识库搭建方法论

> 把散落在硬盘里的文件，变成 AI 能持续维护的第二大脑。
> **三层解耦**：骨架（Markdown Vault）＋ 大脑（AI Agent）＋ 门面（可视化前端）。

---

## 一、先说结论：这套方法长什么样

```
┌─────────────────────────────────────────────────────────────┐
│  门面层  Workbench（可视化前端，可换）                        │
│  总览 / 搜索 / 知识星图 / 阅读器 / 实时跟随                   │
└───────────────────────────┬─────────────────────────────────┘
                            │ 只读挂载 + .env 指向
┌───────────────────────────┴─────────────────────────────────┐
│  大脑层  AI Agent（可换：WorkBuddy / Codex / Claude Code）    │
│  全局提示词 ＋ 12 条斜杠指令 ＋ 2 个定时自动化                 │
└───────────────────────────┬─────────────────────────────────┘
                            │ 读写 Markdown
┌───────────────────────────┴─────────────────────────────────┐
│  骨架层  Markdown Vault（唯一的事实来源）                     │
│                                                              │
│  ┌── 观点层（参与检索/灵感/关联）──────────────┐              │
│  │ 工作项目库 │ 产品洞察库 │ 学习成长库 │ 素材模板库 │          │
│  └──────────────────────────────────────────────┘              │
│  ┌── 库外：原料层 ──┐  ┌── 库外：历史层 ──┐                    │
│  │ _参考库          │  │ 归档             │                    │
│  └──────────────────┘  └──────────────────┘                    │
│  _系统/  索引.md · 标签体系.md · 全局提示词.md · 上手清单.md     │
└──────────────────────────────────────────────────────────────┘
```

**关键设计**：每一层都能单独替换。骨架用任何 Markdown 工具都能打开；换 Agent 只改提示词；换前端只改映射。没有哪一层绑死另一层——这是它能活过三年的原因。

## 二、这套方法解决什么问题

大部分人的知识库死在三个地方：

| 症状 | 根因 | 本方法的解法 |
|:---|:---|:---|
| 文件越堆越多，但用不上 | 没有库边界，什么都能往里扔 | 每个库先写 `README.md` 当"宪法"，明确"适合放入 / **不适合放入**" |
| 检索时先撞上教材原文，而不是自己的判断 | 外部原料与自有观点混在同一棵树 | **观点层 / 原料层 / 历史层物理隔离** |
| AI 帮不上忙，知识在文件夹、AI 在对话框 | 没有给 Agent 稳定的入口与接口 | 全局提示词 ＋ 固定指令集 ＋ 标签即接口 |

一句话概括方法论：**分层解决信噪比，标签解决机器可读，Agent 解决持续维护。**

## 三、核心心法（六条）

### 1. 先定边界，再装内容
建库第一步不是往里丢文件，而是写每个库的 `README.md`：
适合放入什么、**不适合**放入什么、命名规范、必打标签、入库方式。
没有"不适合放入"这一节的库，一定会膨胀成垃圾场。

### 2. 三层物理隔离，唯一判断标准是一句话
> **"这是我产出的，还是别人产出的、我只是搬运的？"**

- 我产出的（判断、方案、复盘、灵感）→ 四库（**观点层**）
- 别人产出的（教材、真题、行业报告、标准原文）→ `_参考库`（**原料层**）
- AI 作业的中间产物（脚本、构建目录、临时文件）→ `归档`（**历史层**）

实测依据：一份备考资料曾占到所属库 **97%** 的体积（3.61 MB / 3.71 MB）。因为 `/检索`、`/灵感`、`/关联` 都是无差别跨库语义扫描，混在一起会直接稀释信噪比。

### 3. 标签是唯一的机器可读接口
文件系统给不了语义，目录名给不了状态。标签承担三件事：
**状态流转**（`#待整理`→`#已消化`→`#精华`）、**分类索引**、**自动化触发**。
五类标签体系见 [`templates/_系统/标签体系.md`](templates/_系统/标签体系.md)。

### 4. Agent 优先，人只看结果
不写"请帮我整理一下"这种话，而是定义**固定指令**：`/入库`、`/检索`、`/写作`、`/复盘`……
每条指令绑定明确的库、明确的输出格式，沉淀成可复用的 Skill。
**能被反复调用的流程，就不该每次重新描述。**

### 5. 缺就是缺，不虚构数据
字段对不上时，页面/报告应保持缺失，不能用 `0` 或编造内容顶替。
这条约束看起来苛刻，但它是知识库可信度的底线——一旦开始编，整套系统就废了。

### 6. 治理是定期动作，不是一次性工作
库会自然膨胀。所以要有**分层治理**这个固定流程（见第四节），
和**定期复盘**这个固定节拍（每周一次）。

## 四、落地路线

### 阶段 1：搭骨架（半天）
1. 建目录：四个库 ＋ `_系统`（＋ 后面再加 `_参考库`、`归档`）
2. 抄 `templates/_系统/` 里的四份系统文档，改成本人背景
3. 抄 `templates/库README/` 里的四份库说明，改边界与标签
4. 写 `_系统/索引.md` 作为总导航（这是你以后唯一需要记的入口）

> 详细步骤见 [`docs/01-骨架-四库设计.md`](docs/01-骨架-四库设计.md)

### 阶段 2：接大脑（半天）
1. 在 Agent 里新开一个工作区，根目录指向 Vault
2. 把 `_系统/全局提示词.md` 的人设写进该工作区的记忆文件
3. 把 12 条指令做成 Skill；把 2 个定时任务做成自动化

> 详细步骤见 [`docs/02-大脑-Agent接入.md`](docs/02-大脑-Agent接入.md)

### 阶段 3：跑一个月（习惯期）

| 周 | 目标 | 动作 |
|:---|:---|:---|
| 第 1 周 | 跑通入库与检索 | 把最近 10 篇文档丢进对应库，用 `/入库` 标准化；用 `/检索` 跨库查一个常问的问题 |
| 第 2 周 | 用起来写与连 | 用 `/写作` 基于知识库写一份真实交付物；用 `/关联` 对一篇核心文档建立连接 |
| 第 3 周 | 项目与复盘习惯 | 用 `/项目` 生成项目知识地图；周日看自动化推送的复盘报告 |
| 第 4 周 | 补齐闭环 | `/灵感` `/学习` `/标签` `/输出` 各试一次；收藏 3 篇文章；上传 1 段会议记录 |

### 阶段 4：分层治理（每 1–2 个月）
体积诊断 → 观点层/原料层分离 → 临时产物归档 → 精华池确权 → 体系文档同步。

> 详细步骤见 [`docs/04-分层治理.md`](docs/04-分层治理.md)

### 阶段 5：接门面（可选，一天）
用开源前端把 Vault 可视化：总览、搜索、知识星图、阅读器、**文件一改页面半秒内自动更新**。

> 详细步骤见 [`docs/03-门面-Workbench接入.md`](docs/03-门面-Workbench接入.md)

## 五、目录结构

```text
your-vault/
├── 工作项目库/            # 观点层：项目全生命周期文档
│   └── <项目名>/          # 按项目分子目录，文档名前缀即文档类型
├── 产品洞察库/            # 观点层：自己的思考 + 外部输入
├── 学习成长库/            # 观点层：系统性学习的提炼结论
├── 素材模板库/            # 观点层：可复用模板与清单
├── _参考库/               # 原料层：教材/真题/标准原文（不参与检索）
│   └── <主题>/
├── 归档/                  # 历史层：AI 中间产物、过期文件（可回滚）
│   └── _临时产物-YYYYMMDD/
└── _系统/                 # 元目录：规则本身
    ├── 索引.md            # 总导航，唯一需要记住的入口
    ├── 标签体系.md        # 五类标签标准
    ├── 全局提示词.md      # Agent 人设
    └── 上手清单.md        # 落地路线
```

**命名规范**

| 库 | 规范 | 示例 |
|:---|:---|:---|
| 工作项目库 | `<文档类型>-<标识>` | `投标-XX项目.md`、`PRD-v1.0.md` |
| 产品洞察库 | `YYYYMMDD-来源-主题` | `20260101-随笔-为什么B端SaaS难做第二增长曲线.md` |
| 学习成长库 | `YYYYMMDD-主题-资料类型` | `20260101-XX考试-论文范文-风险管理.md` |
| 素材模板库 | `<类型>-<名称>-<版本>` | `模板-PRD标准结构-V2.md` |

## 七、踩坑清单（节选）

完整版见 [`docs/05-踩坑清单.md`](docs/05-踩坑清单.md)。

| # | 坑 | 解法 |
|:---|:---|:---|
| 1 | 归档时把一份**有价值分析报告**当临时产物移走了 | 归档前逐个人工确认；**移动而非删除**，保证可回滚 |
| 2 | 索引文件在文件移动后没同步，指向空路径 | 治理流程第 5 步强制"体系文档同步"，列成清单逐项改 |
| 3 | 教材真题混进四库，占 97% 体积 | 原料层物理隔离到 `_参考库` |
| 4 | 灵感池反复 fallback，因为库里没有真实 `#精华` | 精华池只从**观点层**取，不许给教材提炼层批量打 `#精华`，否则反向污染 |
| 5 | 给 `#精华` 计数被正文提及干扰 | 用 `^> ` + 反引号精确匹配，而非裸 `#精华` |
| 6 | 目录移动类命令，无通配符时取到的是"目录内容"而非"目录本身" | 用 `path\*` 让通配符展开 |
| 7 | 前端端口被占后**静默漂移**，用户访问原端口打不开 | 锁定端口 ＋ `strictPort` |
| 8 | 改了后端平台分支，忘了前端文案（"在 Finder 中显示"） | 交付前做一次"能用的功能 + 错的提示"自查 |

## 八、这套方法适合谁

**适合**：知识量在百篇量级、愿意用 Markdown、手上有 AI Agent、想要"自己的判断能被复用"的人。
**不适合**：只想要一个网盘存档的人；需要多人实时协同编辑的人；不接受手动打标签的人。

## 九、脱敏说明

本仓库是**方法模板**，所有示例均为通用占位符（`<项目名>`、`XX考试`、`客户A`）。
不包含任何真实客户名、项目名、内部路径、业绩数据或个人账号信息。
原知识库中的真实内容始终留在本地，从不进入公开仓库。
