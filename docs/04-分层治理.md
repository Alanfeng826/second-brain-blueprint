# 04 · 分层治理：五步流程

知识库不是一次建好的，它会**自然膨胀**。这份流程是定期体检动作，建议 1–2 个月跑一次。

---

## 核心模型：三层分离

| 层 | 物理位置 | 装什么 | 参与 `/检索` `/灵感` `/关联` |
|:---|:---|:---|:---|
| **观点层** | 四库 | 你产出的判断、方案、灵感、复盘 | ✅ |
| **原料层** | `_参考库\<主题>\` | 教材、真题、报告等外部知识的搬运 | ❌ 查阅型 |
| **历史层** | `归档\<批次>\` | AI 中间产物、过期文件 | ❌ |

**唯一判断标准**：*"这是你产出的，还是别人产出你只是搬运的？"* —— 后者进 `_参考库`。

### 为什么必须分层（量化证明）

`/检索` `/灵感` `/关联` 是**无差别跨库语义扫描**。外部原料有两个特征：

1. **体量大** —— 实测：单份备考资料 3.61 MB，占所属库 **97%** 体积（3.61 / 3.71 MB）
2. **非自有产出** —— 检索它 ≈ 翻教材；检索四库 = 复用你自己的判断

混在一起的后果：问"需求工程"，先撞上 43 道历年真题原文，而不是你自己的方法论笔记。

## 步骤 1 · 体积诊断

先量，再动。**按顶层目录统计文件数与体积**：

```powershell
$p = "D:\your-vault"
$all = Get-ChildItem $p -Recurse -File -Force -ErrorAction SilentlyContinue
$lines = @("TOTAL=" + $all.Count + " files / " +
           [math]::Round(($all | Measure-Object Length -Sum).Sum / 1MB, 2) + " MB")
$all | Group-Object { ($_.FullName.Replace($p + '\', '') -split '\\')[0] } |
  ForEach-Object {
    $lines += ($_.Name + " | files=" + $_.Count + " | MB=" +
               [math]::Round(($_.Group | Measure-Object Length -Sum).Sum / 1MB, 2))
  }
$lines | Set-Content "$env:TEMP\kb_stat.txt" -Encoding UTF8
```

> ⚠️ **本环境踩过的坑**：某些终端工具不返回 stdout。写完临时文件后用文件读取工具读。
> 完整脚本见 [`../scripts/kb-stats.ps1`](../scripts/kb-stats.ps1)。

**判据**：任何**单一主题**占某个库体积 > 50%，就是分层信号。

---

## 步骤 2 · 分离原料层

1. 建 `_参考库\<主题>\`
2. 移入**原料**：原始数据、`*.json` / `*.tsv`、大体积 HTML 工具页、真题原文、教材
3. 留在四库的**提炼层**：Markdown 笔记、归纳、地图、索引

**分界口诀**：**"能否被 `/检索` 有效利用？"**
HTML / JSON 基本是噪声（人看可以，语义检索用不上）；Markdown 提炼笔记才是资产。

**必须同步更新**：
- 移动后，原库 README 里凡是引用旧路径的，全部要改
- 四库 README 各加一节"不适合放入"，指向 `_参考库`
- 写 `_参考库/README.md` 说明"为什么它在库外、怎么用"

> 只搬文件不搬文档 = 下次治理时你自己都忘了为什么这么分。

---

## 步骤 3 · 归档临时产物

把根目录的 `_tmp_*` / `_gen_*` / `_manual*` / 构建目录 → `归档\_临时产物-YYYYMMDD\`。

**两条硬规则：**
1. **必须先列清单，移动而非删除**（保证可回滚）
2. **逐个人工确认不是有价值产出**

> **真实事故**：曾把一份**分析报告**当临时产物归档了。归错比不归更糟，因为你会以为它已经清理掉了。

---

## 步骤 4 · 精华池确权

**症状**：`/灵感` 自动化反复 fallback，正文里写"fallback 第 N 次"。
**根因**：不是自动化坏了，是**库里没有真实 `#精华` 文档**。

做法：
- 扫描候选：优先**观点层**文档（你的方法论 / 规划 / 分析）
- **不要**给教材提炼层批量打 `#精华` —— 会反向污染灵感池（灵感应该来自你的判断，不是教材目录）
- 先翻历史周报的"待办清单"，常有点名已久却未执行的
- 目标 **5–8 篇**，打标格式：标题下加一行 `>` + 反引号包裹的标签

```markdown
> `#精华` `#方法论` `#P0核心`
```

---

## 步骤 5 · 体系文档同步（最容易漏，必须做）

| 文件 | 改什么 |
|:---|:---|
| `_系统\索引.md` | 导航拆成「四库 = 观点层」+「库外 = 原料层/历史层」 |
| `_系统\标签体系.md` | 标签增删；停用标签写明停用日期与迁移策略 |
| `<库>\README.md` | 加"不适合放入"边界 + 目录结构表 |
| `_参考库\README.md` | 说明为何在库外、怎么用 |
| 受影响的索引文件 | **修正路径**（文件移动后必须改，否则索引指向空） |

---

## 陷阱清单

| 陷阱 | 说明 |
|:---|:---|
| 目录移动命令的语义 | 无通配符时取到的是"目录**内容**"，不是"目录**本身**"。要移动目录本身，用 `path\*` 让通配符展开 |
| 计数被正文干扰 | 统计 `#精华` 要用 `^> ` + 反引号精确匹配，裸 `#精华` 会把正文提及也算进去 |
| 移动后验证两次 | ① 重列目录树 ② 精确 grep 标签 |
| 别动自建骨架目录 | 遇到疑似自己早年建的骨架目录（如 `10_raw\`），**先报告，不擅自处理** |
| 终端不返回 stdout | 一律写文件再读 |

---

## 输出规范

治理完成后必须给出：

1. **结论** —— 这次治理解决了什么、还剩什么
2. **依据** —— 量化表格（前后体积对比）
3. **行动** —— 2–3 个选项并标注推荐
4. **可回滚位置** —— 归档目录的绝对路径

> 没有"可回滚位置"的治理报告是不合格的 —— 因为它意味着你做了不可逆操作。
