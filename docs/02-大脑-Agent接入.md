# 02 · 大脑：把 Agent 接进来

骨架只是文件。**真正让知识库"活"起来的是 Agent** —— 它负责分类、提炼、关联、写作、定期复盘。

这一层的设计目标是：**让每次交互都不需要重新解释上下文。**

---

## 1. 三个接口，缺一不可

| 接口 | 载体 | 解决什么 | 换 Agent 时的迁移成本 |
|:---|:---|:---|:---|
| 人设 | 全局提示词 | "你是谁、按什么规矩干活" | 粘贴一次 |
| 动作 | 指令（Skill） | "有哪些固定操作可以调用" | 复制 Skill 目录 |
| 节拍 | 自动化任务 | "不等我叫，你自己定期做什么" | 重建定时任务 |

---

## 2. 全局提示词：五段结构

不要写成一段散文。**按职责分段**，Agent 才能稳定执行。

```markdown
【角色设定】
你是我的"第二大脑"和"知识管家"。你熟悉我的工作方式、行业背景和表达习惯。
你的核心职责不是"回答问题"，而是"管理知识、激发连接、辅助产出"。

【记忆规则】
1. 记住我的偏好：<输出风格偏好>
2. 记住我的项目：<当前关注的方向，按实际替换>
3. 记住我的风格：<表达结构偏好>
4. 记住我的阶段目标：<长期目标>

【知识库调用原则】
1. 每次回答优先检索我的知识库（四库），找不到再基于通用知识补充
2. 引用知识库内容时必须标注来源（文档名 + 关键段落）
3. 发现知识库中有矛盾信息时，主动指出并询问以哪个为准

【成长进化规则】
1. 每次交互后，默默记录：我关注的新话题、我纠正过的错误、我反复询问的领域
2. 定期（每周）向我汇报："本周你的知识兴趣变化"和"建议补充的知识盲区"
3. 当我多次以同样方式查询时，主动建议建立 Skill 或自动化任务

【输出规范】
1. 先给结论，再给依据，最后给行动建议
2. 复杂内容用表格或分层列表呈现
3. 涉及方案类输出，必须包含"风险点"和"下一步"
4. 所有输出默认中文，技术术语保留英文
```

**其中三条是这套方法的关键**：
- 「**优先检索知识库，找不到再补充通用知识**」—— 决定了 AI 是你的助手还是搜索引擎
- 「**引用必须标注来源**」—— 让幻觉无处可藏
- 「**发现矛盾主动指出**」—— 知识库会自我发现过时结论

**落到哪里**：写进 Vault 所属工作区的记忆文件（Agent 会自动加载），或写进 Agent 的全局系统提示词设置。
前者只在该工作区生效，后者全局生效。建议**先工作区级，稳定后再考虑全局**。

## 3. 指令集：12 条，分四类

指令不要贪多。**每条指令绑定明确的库和明确的输出格式**，否则它只会变成一段更长的 prompt。

### A. 输入类（东西怎么进来）

| 指令 | 作用 | 绑定库 |
|:---|:---|:---|
| `/入库` | 文档标准化入库：智能分类 → 提取元数据 → 推荐标签 → 关联推荐 → 标记知识缺口 | 全部 |
| 收藏这篇文章 | 网页链接自动抓正文 → 生成入库报告 → 存入洞察库 | 产品洞察库 |
| 整理会议 | 录音转写 / 原始笔记 → 结构化纪要 → 存工作项目库 | 工作项目库 |

### B. 输出类（东西怎么拿出去）

| 指令 | 作用 | 绑定库 |
|:---|:---|:---|
| `/检索` | 跨库语义检索 + 加工后的答案（不是给链接） | 全部 |
| `/写作` | 基于知识库素材撰写方案 / PRD / 投标 / 复盘 | 工作项目库 + 素材模板库 |
| `/输出` | 知识库内容转文章 / PPT 大纲 / 汇报稿 / 培训课件 | 全部 |

### C. 连接类（让它长出网络）

| 指令 | 作用 | 绑定库 |
|:---|:---|:---|
| `/关联` | 发现文档间隐藏联系，构建知识图谱 | 全部 |
| `/灵感` | 跨界联想 + 组合创新 | 产品洞察库 + 学习成长库 |
| `/项目` | 项目知识地图 + 健康度诊断 | 工作项目库 |

### D. 治理类（定期体检）

| 指令 | 作用 | 绑定库 |
|:---|:---|:---|
| `/复盘` | 周 / 月知识成长复盘 | 全部 |
| `/标签` | 标签体系治理（同义合并、废弃低频标签） | 全部 |
| `/学习` | 针对盲区制定学习路径 | 学习成长库 + 产品洞察库 |
| `/分层治理` | 五步分层治理流程 | 全部 |

> 设计原则见 [`06-模板设计要点.md`](06-模板设计要点.md)：
> **每条指令的产出必须落回知识库，而不是只出现在对话框里。** 否则知识库永远不会增长。

## 4. 自动化：让知识库自己长

两个定时任务就能撑起"持续维护"的感觉：

| 任务 | 建议频率 | 做什么 |
|:---|:---|:---|
| **每周知识复盘** | 每周日 21:00 | 扫描本周新增 / `#待整理` 积压 / `#待复盘` 清单 → 输出健康报告 |
| **每日灵感推送** | 每天 9:00 | 从 `#精华` 池抽一篇 + 做一次跨界联想，输出一张卡片 |

**坑（真的踩过）**：灵感池如果库里没有真实 `#精华` 文档，就会陷入重复 fallback，
正文里会写"fallback 第 N 次"。**根因不是自动化坏了，是精华池空了。**
→ 见 [`04-分层治理.md`](04-分层治理.md) 第 4 步"精华池确权"。

---

## 5. 约束：标签是 Agent 的接口，不是装饰

Agent 靠标签做三类判断，所以标签必须**稳定且互斥**：

| 标签类 | 数量约束 | 谁在用 |
|:---|:---|:---|
| 状态 | 必打 1 个 | 治理指令（找 `#待整理` 积压）、复盘 |
| 类型（内容性质） | 打 1–3 个 | `/检索` `/灵感` 的筛选 |
| **文档类型（工作阶段）** | 必打 1 个 | **生成器检索过往范例的主键** |
| 领域 | 打 1–3 个 | 跨库关联 |
| 优先级 | 打 1 个 | 精华池确权 |

> ⚠️ **命名漂移是标签体系的头号杀手。**
> 换方向时（如考试科目变更），旧标签要明确停用策略：
> "存量文档保留不迁移，新文档一律用新标签" —— 并在标签体系文档里写明停用日期。

---

## 6. 接入检查清单

- [ ] 全局提示词五段齐全，且"项目 / 风格 / 目标"已替换为真实内容
- [ ] 提示词已落到工作区记忆文件（或 Agent 全局设置），当前会话已生效
- [ ] 12 条指令中，至少 `/入库` `/检索` `/复盘` 三条可用
- [ ] 每条指令的产出会写回知识库（不只是聊天回复）
- [ ] 两个自动化任务已配置，且时区正确
- [ ] 标签体系文档与指令里实际使用的标签一致（无幽灵标签）
