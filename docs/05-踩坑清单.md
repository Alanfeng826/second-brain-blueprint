# 05 · 踩坑清单（完整版）

全部是真实踩过的坑。**每一条都花过时间，所以能省你的时间。**

---

## A. 设计类（改起来最贵，一开始就要想清楚）

| # | 坑 | 症状 | 解法 |
|:---|:---|:---|:---|
| A1 | 库没有"不适合放入"边界 | 半年后每个库都变成杂物间，检索全是噪声 | 每个库 README 必须有这一节，且要写具体反例 + 判断标准 |
| A2 | 原料混进观点层 | 问一个问题先撞上教材原文 | 物理隔离到 `_参考库`；实测单份资料可占库 97% 体积 |
| A3 | 给教材提炼层批量打 `#精华` | 灵感池被教材目录污染，推不出有价值的东西 | 精华池**只从观点层取** |
| A4 | 标签命名漂移 | 同一个意思出现 `#竞品` 和 `#竞品分析`，检索漏召回 | 每月跑一次标签治理；方向变更时明确"存量不迁移，新文档用新标签"并写停用日期 |
| A5 | 一次性大迁移历史文件 | 规则还没验证，错误规则被套到全部历史数据上 | **先让新东西按新规则进来**，旧文件在第一次治理时分批搬 |
| A6 | 规则只存在脑子里 | 换机器/换 Agent 就重来一遍 | 规则文件化进 `_系统/`，跟着 Vault 走 |
| A7 | 缺数据时用 `0` 或假数据顶替 | 页面上看起来"有数据"，实际是假的，可信度崩掉 | 硬约束：**缺就是缺**。字段对不上页面就留空 |

## B. 骨架/文件操作类

| # | 坑 | 症状 | 解法 |
|:---|:---|:---|:---|
| B1 | 目录移动命令语义 | 想移动目录，结果只移动了它的内容 | 无通配符时取到的是"目录内容"；要移动目录本身用 `path\*` |
| B2 | 归档误伤 | 把一份**有价值的分析报告**当临时产物移走了 | 归档前逐个确认；**移动而非删除** |
| B3 | 文件移动后索引没同步 | 索引指向空路径，导航点进去 404 | 治理流程第 5 步强制"体系文档同步"，列清单逐项改 |
| B4 | 标签计数被正文干扰 | 统计 `#精华` 数量远大于实际 | 用 `^> ` + 反引号精确匹配，而非裸 `#精华` |
| B5 | 索引文件本身就是噪声源 | 手写的 `导览.md` 内容重复、越写越旧 | 删除独立导览文件，导航统一收进 `_系统/索引.md` 一处维护 |
| B6 | 擅自处理疑似自建目录 | 把用户早年建的骨架目录（如 `10_raw\`）当垃圾清了 | 遇到不认识的骨架目录**先报告，不擅自处理** |

## C. Agent / 提示词类

| # | 坑 | 症状 | 解法 |
|:---|:---|:---|:---|
| C1 | 提示词写成散文 | Agent 执行不稳定，每次理解都不一样 | 按职责分五段：角色 / 记忆 / 调用原则 / 进化 / 输出规范 |
| C2 | 没写"优先检索知识库" | AI 退化成搜索引擎，你的判断永远用不上 | 明确写"优先检索四库，找不到再补充通用知识" |
| C3 | 没写"引用必须标注来源" | 幻觉无法被发现 | 强制标注「来源：《文档名》」 |
| C4 | 指令产出只停留在对话框 | 用了三个月，知识库一条没长 | 每条指令的产出必须**落回知识库** |
| C5 | 提示词塞在错误的位置 | 以为全局生效，实际只在一个工作区 | 区分"工作区级记忆文件" vs "Agent 全局设置"；先工作区级验证 |
| C6 | 自动化 fallback 空转 | 周报/灵感报告正文写"fallback 第 N 次" | 根因多半是**精华池为空**，先确权 `#精华`，不要去改自动化 |

## D. 前端接入类

| # | 坑 | 症状 | 解法 |
|:---|:---|:---|:---|
| D1 | 非 `VITE_` 前缀的环境变量不注入 | 改完 `.env` 站点还在读 demo | **完全重启** dev server；用 `/api/runtime` 验证读的是哪个目录 |
| D2 | 镜像模式看不到新写入 | "知识库天天更新，站点数据不动" | 监听器只挂在镜像根；要实时就**直读源目录**，污染用排除规则解决 |
| D3 | 排除规则漏了文件分支 | 顶层 `_tmp_*.md` 出现在列表里 | 前缀排除**在文件分支也要检查一次** |
| D4 | 发明新的 section 名 | 分类规则写了，前端不认，文件全部落到默认分类 | `section` 必须用**上游已有的视图名**，你只做"翻译"不做"扩展" |
| D5 | 端口静默漂移 | 用户访问原端口打不开 | 显式声明 `port` + `strictPort: true` |
| D6 | 后端做了平台分支，前端文案没跟 | Windows 上提示"在 Finder 中显示" | 平台文案抽成常量；交付前做一次"能用的功能 + 错的提示"自查 |
| D7 | macOS-only 命令没做 win32 分支 | dev server 直接崩掉（ENOENT） | `process.platform === "win32"` 分支，用 `explorer.exe` / `cmd /c start` |
| D8 | Vite HMR 不重启 plugin 顶部 import | 改了插件代码，行为没变 | 改插件顶部逻辑后必须 **kill 进程 + 重启**，HMR 不覆盖 cold path |
| D9 | 通过 Agent 的终端启动常驻服务 | Agent 一关，进程树被清理，站点打不开 | 独立启动器 + detached spawn；用父进程链验证是否孤儿化 |
| D10 | VBScript 保留字当变量名 | 编译期直接报"缺少标识符"，不是运行时 | 保留字清单：`sub/function/property/class/object/len/left/right/mid/error/name/date/time/string/item/me/let/set/dim/new/next/step/to/each/in/is/not/and/or/mod/empty/null/true/false/nothing`。注意 `subFolder` 是**合法**的（按最长标识符匹配） |
| D11 | 脚本文件行尾 | Windows 脚本用 LF 在某些环境出错 | `.vbs` / `.bat` 用 **CRLF** |

## E. 环境/工具类（本机特定，但很典型）

| # | 坑 | 症状 | 解法 |
|:---|:---|:---|:---|
| E1 | 终端工具不返回 stdout | 命令 exit 0 但输出为空 | **写临时文件再用文件读取工具读**。这是最容易浪费时间的坑 |
| E2 | `dirname` / `head` 等命令缺失 | shell 脚本报 `command not found` | 环境为精简版 PortableGit；改用 PowerShell 或 Node 脚本 |
| E3 | 系统命令被安全策略拉黑 | `reg.exe` 等被拦 | 换 PowerShell 等效实现（查注册表：写文件再读） |
| E4 | 未签名脚本/应用被系统完整性策略拦截 | 报 `0xc0e90002`（STATUS_SYSTEM_INTEGRITY_POLICY_VIOLATION） | 属于系统级策略（如 Smart App Control），需用户自行决定是否关闭；**关闭不可逆**，必须先说清影响 |
| E5 | Agent 内无法验证 `.vbs` | 沙箱按 LOLBin 拦截 `wscript`/`cscript` | `.vbs` 只能静态复查 + **让用户双击跑一次**。只验证"等价逻辑"（Node 版）会漏掉编译期错误 |

> **E5 的通用教训**：**交付任何启动入口后，必须让用户实际执行一次才算验证过。**
> "等价逻辑跑通了"不等于"这个文件能跑"。

## F. 流程/习惯类（不写代码也会踩）

| # | 坑 | 症状 | 解法 |
|:---|:---|:---|:---|
| F1 | 建完库就不管了 | 三个月后膨胀到不可维护 | 固定治理节拍：每周复盘 + 每 1–2 月分层治理 |
| F2 | 治理报告没有可回滚位置 | 出了问题无法回退 | 治理输出必须含"归档目录绝对路径" |
| F3 | 追求一次到位 | 规则没验证就大规模应用，返工成本极高 | 阶段化：第 1 周只跑通入库/检索，第 4 周才补闭环 |
| F4 | 把方法当工具 | 换工具就重来 | 记住分层：骨架/大脑/门面各自可换，方法不依赖于任何具体工具 |

---

## 一句话总结

**这套方法里最难的不是技术，是"克制"**：
克制往库里丢东西的冲动（边界）、克制用假数据补齐的冲动（可信）、
克制一次改到位的冲动（阶段化）、克制删掉文件的冲动（可回滚）。
