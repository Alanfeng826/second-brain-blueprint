# 🧩 素材模板库

存放**可复用的资产**。这是"搭积木的零件盒"，让 `/写作` `/输出` 能直接调用。

---

## 适合放入

- PRD 模板、汇报 PPT 大纲模板
- 流程图、检查清单（Checklist）
- 金句库、数据案例库
- 常用提示词、邮件 / 沟通模板
- **通用框架**（如"XX 类投标技术标通用骨架与标准业绩池"）

## 不适合放入

- **已经填了具体项目内容的成品文档** → 放 `..\工作项目库\<项目名>\`
- **原始素材本身**（如设计稿源文件、大体积素材包）→ 放库外 `_参考库` 或直接用文件系统管理

> 判断标准：**"这份东西下次能被另一个项目直接套用吗？"** 能 → 本库；不能 → 工作项目库。

---

## 命名规范

`<类型>-<名称>-<版本>`

例：`模板-PRD标准结构-V2`
　　 `清单-投标技术方案自查表`
　　 `框架-<行业>技术标通用骨架-业绩池`

详见 `..\_系统\标签体系.md`

## 目录结构

按**工作阶段**分目录，不要按文件格式分：

```text
素材模板库/
├─ 售前文档/            # 需求收集、需求分析汇总、方案设计、客户报价、立项文档、投标文件
├─ 产品设计文档/        # PRD、项目进展汇报
├─ 文档体系图谱.md      # 总导航：阶段 → 文档类型 → 模板 → 过往范例 → 生成指令
└─ README.md
```

### 每个模板应包含

| 章节 | 内容 |
|:---|:---|
| 适用阶段 | 什么时候用它 |
| 输入 | 需要哪些前置材料 |
| 输出结构 | 章节 + 填写指引（**这是主体**） |
| 关键提示 | 容易写错的地方 |
| 范例引用说明 | 生成器要去工作项目库找哪类范例做对齐 |

> **为什么模板要写"关键提示"**：模板解决"结构对不对"，
> 关键提示解决"内容专不专业"。后者才是模板的真正价值所在。

---

## 文档体系图谱的作用

`文档体系图谱.md` 是本库的总导航，把"工作阶段 → 该产出什么文档 → 用哪个模板 → 去哪里找过往范例"连成一条线。
它是文档生成器的**路由表**：Agent 靠它决定该加载哪个模板、该检索哪个项目目录。

---

## 入库方式

模板 / 清单直接放入。

- 写项目文档时，文档生成器会自动**加载本库模板 + 检索工作项目库同类型范例**
- `/写作` 也会检索本库作为素材来源
- 用得多了发现某个模板总被改同样的地方 → **把改动吸收回模板本体**，这是模板进化的唯一方式
