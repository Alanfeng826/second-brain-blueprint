# 📁 工作项目库

存放**项目全生命周期文档**。这是"正在发生的事"的沉淀地。

---

## 适合放入

- PRD、需求评审记录、原型说明
- 投标技术方案、交付物
- 项目复盘、会议纪要
- 关键决策记录

## 不适合放入

- **项目用到的外部原始资料**（产品手册、行业标准原文、竞品截图）→ 放库外 `..\_参考库\`
- **跨项目复用的模板与清单** → 放 `..\素材模板库\`
- **不针对具体项目的行业思考** → 放 `..\产品洞察库\`

> 判断标准：**"这是针对某个具体项目的产出吗？"** 不是 → 去别的库。

---

## 目录约定（按项目归档）

真实项目文档按**项目名**分子目录存放，每篇打对应的「文档类型标签」，供生成器检索过往范例：

```text
工作项目库/<项目名>/
├─ 需求收集-<客户>.md    # 文档类型标签 #需求收集
├─ 需求分析-<客户>.md    # #需求分析
├─ 方案设计-<客户>.md    # #方案设计
├─ 报价-<客户>.md        # #报价
├─ 立项-<项目名>.md      # #立项
├─ 投标-<项目名>.md      # #投标
├─ PRD-<版本>.md         # #PRD
└─ 进展-<周期>.md        # #进展汇报
```

> 文档类型标签完整清单见 `..\_系统\标签体系.md`。
> **优质范例额外打 `#范例`，生成器优先套用它。**

### 为什么按项目分子目录

因为**不同项目的同类文档必须能被区分**。
否则你写新项目投标书时，Agent 会在全库模糊搜索里抓出别的项目的报价数字。

分子目录 + 文档类型标签之后，"检索同类历史范例"就变成一次**精确的目录内查询**。

### 项目索引

在本节维护一份项目清单，每条写明：项目名 / 目录 / 关键文档与标签。

```markdown
- **<项目名>**（`<项目名>/`）—— <一句话说明>（#<文档类型> #<领域>）
- **<项目名>**（`<项目名>/`）—— <一句话说明>（#<文档类型> #<领域> #范例）
```

> 这份索引要手写维护。它同时服务于**人**（快速回看）和**Agent**（知道有哪些项目存在）。

## 命名规范

`<文档类型>-<标识>`（置于项目子目录内）

例：`投标-XX项目v1`、`PRD-V2.0核心功能`

> 跨项目总览性文档仍可用 `YYYYMMDD-项目名-文档类型-标题`。

---

## 必打标签

详见 `..\_系统\标签体系.md`

- **状态**：`#待整理` `#已消化` `#待复盘` `#精华` `#过期`
- **文档类型（必打 1 个）**：`#需求收集` `#需求分析` `#方案设计` `#报价` `#立项` `#投标` `#PRD` `#进展汇报`
- **类型**：`#PRD` `#流程` `#复盘` `#投标` `#案例`
- **领域**：`#<你的行业标签>`
- **优先级**：`#P0核心` `#P1重要` `#P2参考`

---

## 入库方式

- **写项目文档**：直接说文档类型（如"给 XX 项目写方案"），由文档生成器加载模板 + 检索范例生成并存回本库
- **已有文档入库**：对 Agent 说 `/入库`；网页资料说"收藏这篇文章"
- **定期体检**：用 `/项目` 生成项目知识地图与健康度诊断
